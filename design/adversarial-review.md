# 用户视角对抗性审查

## 已修复的问题

- 原页面要求先理解 agentDir 和 profile。现在用户只添加工作目录。
- 原页面把全局配置混入主流程。现在全局 `~/.pi/agent` 完全不读取。
- 原页面同时提供“添加配置目录”和“添加实例”。现在只有“添加工作目录”。
- 原页面只显示 Server 状态，容易忽略已配置 Client。现在顶部显示工作区整体连接摘要，Server 细节独立呈现。
- 原实现所有实例默认 `9910`。现在新增实例自动分配稳定端口。
- 原实现只显示 registry 是否存在。现在区分配置端口、实际端口、fallback、冲突和其他进程占用。
- 原流程启用 Server 时可能没有凭据而启动失败。现在自动进入连接方名称步骤并生成 Token。
- 运行状态使用系统 agentDir 下不含密钥的 registry；同 cwd 有 Pi 但没有登记时只标记为未确认，不推断其进程环境。
- 原并发初始化可能选中相同端口或覆盖状态。现在初始化串行执行并在每次开始时重新读取状态。
- 将 SFTP 放进 Agent 页签会颠倒所有权。文件空间现在是独立应用模块，Agent 只是多对多关联方。
- 自研 HTTP/SFTP、续传或任务队列会扩大风险。现在只监督 rclone 进程，传输能力全部复用 rclone。
- 创建时暴露全部网络参数会增加无效操作。现在默认只需目录、密码和 Agent，高级参数自动建议并折叠。
- 删除文件空间容易误解为删除文件。第一版不提供删除，只允许停用并明确保留目录内容。

## 防误操作

- 已有 `.pi/settings.json` 永不修改。
- 已有 `.pi/agent/settings.json.a2a` 初始化时永不修改。
- 已有端口冲突只提示，不擅自改端口。
- 插件安装失败保留配置并显示重试命令。
- 所有后续编辑必须先看差异，再通过 hash 检查写入。
- 启用 Server 会合并已有草稿；同一草稿中的新增和删除 secret 不会互相覆盖。
- 删除工作目录只删除 A2A Config 的登记，不删除项目文件。

## 用户完成标准

系统 Pi 已配置 `pi-a2a` 时，用户只输入一个工作目录即可得到系统 `a2a.profiles[cwd]`、合法身份、唯一 workspace、稳定端口和可复制启动命令。工具不安装插件。
