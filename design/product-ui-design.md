# A2A Config 产品与 UI 设计

## 产品目标

用户只需理解“Agent 工作目录”“连接另一台 Pi”和“文件空间”。工具隐藏 agentDir、scope、工具权限和传输协议实现细节。

主流程：

```text
添加工作目录
  -> 检查现有 .pi
  -> 创建系统 Pi profile / 配置 A2A
  -> 查看 Server 状态
  -> 添加连接方并启用 Server
```

## 页面结构

- 顶栏：刷新、唯一主操作“添加工作目录”。
- 左侧：工作目录列表，不显示全局配置层级。
- 主区顶部：Agent 名称、工作目录、启动命令、工作区连接摘要和 Server 启用/关闭按钮。
- 次级页签：Server、连接其他 Pi、允许其他 Pi 连接。
- 顶栏使用“Agent 配置 / 文件传输”模块切换。文件传输是应用级独立页面，不属于某个 Agent 页签。
- 运行参数不进入主流程；只保留地址、端口、备用端口、对外地址和 workspace ID。

## 添加工作目录

对话框只有一个目录输入框：

1. “检查目录”只读检查项目 A2A、系统 profile、系统插件状态、旧专属配置和建议端口。
2. 检查结果明确说明哪些文件会创建、哪些现有内容不会修改。
3. “添加并配置”显示检查、创建、配置、安装、完成五个阶段。
4. 安装失败时显示失败原因和可复制重试命令；再次点击可重试。
5. 完成后关闭对话框并选中新工作目录。

## 连接与 Server 状态

状态区位于页签之前，使用文字和颜色共同表达：

- 尚未配置连接
- 已配置连接（存在出站 peer、入站连接方或 Server 已启用）
- 插件安装中
- 等待 Pi 启动
- 运行中
- 使用备用端口
- 端口冲突
- 启动异常

Server 默认关闭。点击启用时：

- 已有连接方 Token：直接进入配置差异预览。
- 没有连接方 Token：打开只包含连接方名称的步骤，Token 自动生成，随后进入统一差异预览。
- 已有未保存草稿：与 `enabled=true` 和新连接方一起进入同一次差异预览。

## 端口提醒

- 左侧冲突 Agent 右侧显示橙色 `!`；实际端口重复显示红色 `!`。
- hover/focus 文案包含冲突 Agent 和端口。
- Server 状态区下方列出全部冲突原因。
- 编辑端口时即时对比其他已管理 Pi；保存后由后台状态接口复核系统占用。
- fallback 文案必须说明“当前可用，但重启后地址可能改变”。

## 连接配置

- 出站连接：名称、URL、Token；验证只读取 Agent Card 和不存在的 Task，不发送模型任务。
- 入站连接：用户只填写身份名称，工具自动生成 Token 和底层最小配置；远端 Pi 必须使用同一个身份名称和 Token。
- Token 按用户要求明文显示。
- Prompt 根据 Agent 名称、实际/配置端口、`publicUrl`、连接方名称和 Token 即时生成，不保存副本。

## 响应式规范

- 桌面：`280px` 左栏，主区自适应。
- 小于 `900px`：左栏改为抽屉。
- 小于 `640px`：表单单列、状态区纵向排列、保存栏固定底部。
- 字体、颜色和控件尺寸沿用现有静态规范：正文 `14px`、标题 `20px`、控件高 `36px`、圆角 `6px`、主色 `#176B5B`、警告 `#B54708`、错误 `#B42318`。

## 数据边界

- 工具状态只保存工作目录真实路径。
- `.pi/settings.json` 只读。
- 完整配置只写 `.pi/agent/settings.json` 和 `.pi/agent/.env.local`。
- 不读取或修改 `~/.pi/agent/settings.json`。
- 不缓存 Agent Card、端口状态、运行状态或 Prompt。
- 插件运行登记只包含 PID、cwd、instanceId 和时间，不包含环境变量或 Token。

## 文件传输模块

- A2A Config 管理多个独立文件空间；每个文件空间映射一个任意现有、可读写的真实目录，同一目录禁止重复。
- 创建时用户输入密码并至少选择一个 Agent；名称和用户名默认目录名，地址与端口自动建议，高级设置默认折叠。
- 一个文件空间可关联多个 Agent，一个 Agent 可关联多个文件空间；不提供权限分级。
- 创建成功立即启动 rclone SFTP。文件空间只可停用，不可删除；停用保留文件、凭据、host key 和绑定。
- 详情页采用状态、目录、关联 Agent、高级设置四个无卡片区块。完整 HTML 规范见 `file-transfer-html-spec.md`。
